安装与升级

一键脚本默认装 dae、daed 和 LuCI 三件套，并顺带下载 GeoIP / GeoSite 依赖。

一键安装

wget -O - https://cdn.jsdelivr.net/gh/kenzok8/openwrt-daede@main/scripts/install.sh | ash

镜像没同步到最新脚本时，直连 GitHub：

wget -O - https://raw.githubusercontent.com/kenzok8/openwrt-daede/refs/heads/main/scripts/install.sh | ash

只要 daed 后端：

wget -O - https://raw.githubusercontent.com/kenzok8/openwrt-daede/refs/heads/main/scripts/install.sh | DAEDE_CORE=daed ash
这个脚本只装包，不会把软件源写进系统。想在 LuCI 里持续在线升级，还要按下面「软件源」那节配一次。

之前只装过 daed 的设备，重跑默认命令就会补装 dae，不用先配软件源。

换加速站：

GITHUB_PROXY_PREFIX=https://你的加速站/ wget -O - https://cdn.jsdelivr.net/gh/kenzok8/openwrt-daede@main/scripts/install.sh | ash

软件源

wget -qO- https://down.dllkids.xyz/openwrt-feed/openwrt-feed-setup.sh | sh

脚本会检测 SDK 版本与架构、下载公钥、写源配置、刷索引 —— 只配源不装包。之后从 LuCI 的软件包页或命令行升级：

apk update && apk upgrade                            # 25.12
opkg update && opkg upgrade luci-app-daede dae daed   # 24.10
该脚本在 apk update 失败时会尝试 --allow-untrusted。看到这条警告说明验签没通过，先修源或公钥，别把放宽校验的结果当成已验证。

依赖

包名用途
ca-bundleCA 证书
kmod-sched-core / kmod-sched-bpfeBPF 调度与流量分类
kmod-veth虚拟以太网设备
kmod-xdp-sockets-diagXDP socket 诊断
kmod-nft-tproxynftables TPROXY

dae / daed 二进制由 luci-app-daede 的 Makefile 自动拉对应后端包，不用手动装。

先确认 BTF

[ -e /sys/kernel/btf/vmlinux ] && echo 有 BTF || echo 缺 BTF，需补包

缺的话看内核 BTF —— 这是 daed 起不来的头号原因。

卸载

wget -O - https://raw.githubusercontent.com/kenzok8/openwrt-daede/refs/heads/main/scripts/uninstall.sh | ash

维护者发布流程

手动发代码修复：Actions 里跑「Sync and release dae/daed」选 current，等候选检查与 16 目标构建通过后，在测试设备上复测包，再在「Promote verified daede candidate」里填运行摘要中的候选 SHA。晋升复用已验证的包并等公开源聚合完成。

release.yml 单独跑只出候选包，不会更新公开源；定时上游同步仍按 core / perf 检查、验证、自动晋升，ENABLE_UNATTENDED_RELEASE 只控制定时那次是否自动发布，不影响手动 current 候选构建。
