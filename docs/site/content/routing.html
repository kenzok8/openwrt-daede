订阅、分组与路由

三块拼起来才是一条完整链路：订阅 / 节点提供原料，分组把节点分堆，路由决定哪股流量用哪堆。

订阅和节点的区别

订阅节点
填什么机场给的 https:// 订阅链接单条 vless:// ss:// vmess:// 分享链接
一个链接 =一批节点一个节点
能更新吗能，机场会更新节点不能，链接写死了

所以「订阅」表里：真订阅那一行「更新」是亮的；固定分享链接那一行「更新」是灰的（提示「固定链接，无需更新」）—— 这是正常现象，不是坏了。

固定的单节点链接其实更适合放进「节点」表，语义更清楚。

分组：把节点分堆

分组（如 proxy、AI）是路由的目标。每个分组三项：

项目怎么填
名称随便起，路由里要原样引用
策略最小移动平均延迟（推荐，稳）、最小最近延迟（激进）、随机、固定第一个
来源订阅 / 节点名匹配都留空 = 全部节点；填了就把匹配的包含进来，多条件之间是「或」

「节点名匹配」每行一个关键词，多行之间是「或」：

香港
台湾

也可以一行用竖线写正则，效果一样：

香港|台湾
别用空格分隔 —— 香港 台湾 会被当成一整串，一个都匹配不到。

「来源订阅」+「节点名匹配」一起填也是「或」：来源订阅 = mying 配 节点名匹配 = vps，这个分组就同时包含机场全部节点和你那条叫 vps 的单节点。

路由：哪些流量走代理

开关 / 字段默认作用
私网直连开局域网与内网地址不代理
国内直连开国内网站和 IP 直连
拦截广告关命中广告域名列表直接掐断
兜底分组—上面都没命中的流量走哪个分组

自定义规则

格式永远是 匹配条件 -> 目标，一行一条，在兜底之前生效。目标只能是三种：分组名、direct、block。

domain(geosite:openai) -> AI
domain(suffix: youtube.com) -> proxy
dip(geoip:jp) -> proxy
dip(1.1.1.1) -> direct

条件可以组合：&& 是「并且」，! 是「排除」。

domain(geosite:cn) && !domain(suffix: speedtest.cn) -> proxy
箭头右边的分组名必须和实际建的一模一样，否则保存时报「校验失败」。
